# Comic-Lab v2.42：背景画像が隣のコマに見える不具合

対象ブランチ: `feature/v2-panel-layout`。基準: v2.41α `b6864c3`。

## 原因

添付スクリーンショットの「上段2コマ・下段1コマ」を再現すると、左上の背景画像が右隣の通常コマに見えました。画像の座標は変化していません。

背景への切替時は、従来どおり画像のクリッピングがOFFになります。元画像がコマの外まで描画されますが、前面の通常コマは枠線と画像だけを描き、コマ内の塗りがありませんでした。このため空の右隣コマや下段コマが透明になり、背面画像が透けていました。

v2.41αではマスクが背景コマ自身を隠す問題を修正しましたが、通常コマの不透明な面がない問題が残っていました。

## 修正

共通SVG描画 `src/panel-images.ts` で、背景コマがあるページの通常コマをページ背景色で下塗りし、その上にコマ内画像を描画します。

描画順序:

1. ページ背景・背景コマ
2. 余白マスク（設定に応じて）
3. 各通常コマの多角形に沿ったページ色の面、そのコマの画像
4. 通常コマ枠線
5. 吹き出し・セリフ

空の通常コマや、透明PNGの透明部分はページ色になります。斜めコマは実際の多角形で塗るため、その外接矩形で背景を不必要に隠しません。枠線の表示／非表示とは独立して前面の面を描画します。

背景画像自体の位置・倍率・オフセット・元バイト列・クリッピング設定は変更しません。保存形式やデータ移行も変更しません。v2.41αのZIPを開き直した場合にも修正版の描画が適用されます。

背景コマがないページは従来の描画を維持します。背景をコマ間に表示する設定も維持し、通常コマの内部への透けとは分離します。

## 検証結果

`npm test` **146件**、`npm run build`、`git diff --check` 成功。

- 背景表示ON/OFFで、背景画像より後・枠線より前に通常コマのページ色面を描くこと。
- 通常コマの画像より先に下塗りし、その画像を隠さないこと。
- 背景画像の拡大、クリッピングON/OFFでも座標が同一であること。
- 斜めコマの形状を下塗りにも使用すること。
- 既存データを変更せずZIP復元後の共通SVGが一致すること。

独立SVGラスタライザーで、スクリーンショット相当の配置・拡大背景・斜め通常コマ・透明PNGの4ケースを背景表示ON/OFFで検証しました。

- 修正前の構成では右コマ内へ画像が透け、修正後は同じ点が白いページ色になりました。
- 右隣と下段の空コマが不透明で、通常コマの画像の有色部分は表示されました。
- 透明PNGの透明部分はページ色となりました。
- 斜めコマの輪郭外では、表示を許可した背景が残りました。

- ZIP復元後の全PNGが一致しました。

v2.41αの位置調整・拡大・斜め変形・クリッピング切替の画像座標と600サンプルの内部画素検証も引き続き成功しています。
