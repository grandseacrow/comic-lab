# Comic-Lab v2.41α：背景切替時の画像表示

開発ブランチ: `feature/v2-panel-layout`。

プレビュー: https://feature-v2-panel-layout-comic-lab.kairi-sakusaku.workers.dev/

## 調査と原因

今回GitHubと指定URLで確認できた基準はv2.15α（`ca5a65e`）でした。v2.4αと記載された別のソースやスクリーンショット自体は確認できていませんが、現行コードで「選択枠内が白く、下側にだけ画像が見える」という再現ケースを作成しました。

通常／背景の切替はkind・枠線・clipImageだけを変更します。画像のx/yはどちらも同じ関数で `panelBounds.x/y + image.offsetX/Y` として描画しており、二重translateやCoverの再計算はありませんでした。

再現例の画像描画値は、切替前後とも **x=40、y=-85、width=550、height=1100** で同一です。コマ頂点、offset、scaleも同一でした。それでも「コマ間の背景を表示」がOFFのとき、次の処理により表示が欠けていました。

1. 背景画像を正しい原稿座標へ描画。
2. 通常コマの外側をページ背景色で覆うマスクを重ねる。
3. 背景へ切り替えたコマは通常コマ一覧から外れるため、自分自身の領域もマスクされる。
4. 画像が下の通常コマにまで広がっている場合、その部分だけが残り、下方向へ移動したように見える。

再現例では選択枠内の(300,300)が白、下のコマ内の(300,950)に画像が残りました。これは原稿の座標ずれではなく、背景コマ本体まで覆う余白マスクの範囲誤りです。

## 修正

`src/panel-images.ts` の余白マスクから、通常コマに加えて **画像を持つ背景コマ自身の輪郭** を除外しました。変更は共通SVG描画処理に置き、編集画面とPNG出力に同じ結果を適用します。

- kind変更・クリッピングON/OFFで画像の基準座標は変更しません。
- 点線選択枠と同じ頂点から、クリッピングとマスク除外領域を生成します。
- 背景は第3層、通常コマは第2層のままです。
- 枠線とclipImageは従来どおり独立しています。
- 元画像・オフセット・倍率・頂点・保存形式は変更しません。

背景表示OFFは、各コマの領域外（コマ間・外周余白）に作用します。背景コマ自身は隠しません。そのためページ全面の背景コマは、OFFでも自身の範囲に表示されます。ONでは各コマ領域外にも背景のはみ出しが表示されます。

## 回帰検証

`npm test` **142件**、`npm run build`、`git diff --check` 成功。

- A 基本: 位置調整後に通常→背景→通常を切替。頂点・画像データ・描画x/y/幅/高さが同一。背景自身の輪郭を白いマスクから除外していることを検証。
- B 拡大後: 画像中心を維持して拡大してから切替。倍率と原稿上の描画位置が同一。
- C クリッピング: ON/OFFと枠線ON/OFFの全組み合わせで、画像原点を維持。表示範囲だけが変わることを確認。
- D 斜め: 凸四角形の頂点と画像の基準位置を維持し、同じ多角形をクリッピングとマスクに使用。
- E 保存・出力: 実際のZIP読込関数で素材・位置・倍率・clipImage・頂点を復元し、共通SVGが完全一致。
- 実際のAppハンドラーでも位置調整・拡大後のkind変更とクリッピング切替を通し、画像のSVG座標が変わらないことを検証。既存のUndo/Redoと保存復元テストも成功。

追加で独立したSVGラスタライザーを使用し、位置調整・拡大・斜めの3ケースを画像化しました。選択枠内部の600サンプルで、通常→背景切替前後の画素が一致。クリッピングONでも内部画素が一致し、元の通常コマへ戻した全PNG、ZIP復元後の全PNGも完全一致しました。コマ外のガターでは背景表示ON/OFFが作用することも確認しています。

## 確認範囲

この修正は、現行公開コードで再現したマスク起因の表示欠けを対象とします。実ブラウザ操作ツールがないため、実機のタッチ・マウス・ブラウザCanvas出力は未確認です。ハンドラーテストのDOM・画像デコードは代替、画素検証は独立SVGラスタライザーです。

main・本番Workers・旧Pages・Wranglerプレビュー設定・シークレットは変更せず、alphaブランチのプレビューだけを更新します。
